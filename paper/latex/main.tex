\begin{abstract}
Sensory Perceiver is a multimodal architecture that combines modality-specific towers with shared cross-modal attention in settings where systems must keep learning over time. The implementation keeps modality identity explicit through runtime-validated MIME-style contracts, while the current empirical core is a replay-centric continual-learning program built on the attention and latent-bottleneck lineage running from Transformers to Perceivers \citep{cite1,cite2,cite3}. On Split-CIFAR-100, feature-only replay fails with severe forgetting (CIL 4.86\%, BWT $-53.80\%$), raw-input replay with reservoir sampling materially improves retention (CIL 19.54\%, BWT $-34.91\%$), and the current tuned-core configuration improves the multiseed mean further to CIL 23.96\% and BWT $-30.39\%$ over six Titan runs. The strongest mechanistic conclusion is therefore that replay signals must reach shared feature extractors, not only late task heads.

The strongest completed perception-side evidence is the hardened synthetic sensor-routing ladder, where typed canonical routing outperforms merged routing on the baseline, capacity-matched control, leave-one-out branches, corruption branch, and two of three single-modality noise branches, with \texttt{noise\_robot\_arm} as the main exception. Real-data evidence is now reported conservatively with an explicit bootstrap-versus-canonical split: bootstrap runs on Speech Commands and WISDM are includable now, \texttt{real-audio-seq-003} is the first promotable canonical integrated audio sequence, and \texttt{real-sensor-seq-002} is now the promotable canonical integrated sensor sequence. The current contribution is therefore a disciplined blueprint for building domain-specific perception systems: keep modality identity explicit, validate routing semantics at the runtime boundary, and make continual-learning safeguards act on the shared perceptual backbone.
\end{abstract}

\section{Introduction}

Sensory Perceiver is motivated by a simple systems question: how should a perception model be structured if it must ingest heterogeneous sensory inputs, keep modality identity explicit, and continue adapting without full retraining each time new data arrives? Attention-based sequence models made it practical to reason globally over flexible input sets \citep{cite1}, while the Perceiver family showed that a shared latent bottleneck could extend that flexibility to large, heterogeneous perceptual inputs \citep{cite2,cite3}. The repository's answer combines three ideas:
\begin{enumerate}[leftmargin=*]
  \item modality-specific towers preserve sensor identity rather than collapsing heterogeneous streams into one generic input;
  \item a shared cross-modal core integrates those streams into a common latent representation;
  \item replay-centric continual learning attempts to preserve that shared representation over time.
\end{enumerate}

The broad framing is machine perception, but the evidence is intentionally bounded. The strongest validated result remains the continual-learning lane on Split-CIFAR-100. The strongest completed perception-side result is the synthetic sensor-routing ladder. Real-data support exists as bootstrap evidence on Speech Commands and WISDM, and the first canonical integrated audio and sensor sequences are now promotable because their bounded reports completed unblocked. This manuscript follows that evidence boundary rather than the broadest architectural ambition.

\section{Related Work}

Sensory Perceiver sits at the intersection of multimodal integration, continual learning, and systems-oriented runtime design. The architectural lineage runs through attention-based sequence models \citep{cite1,cite4,cite5,cite6,cite7} and the Perceiver family \citep{cite2,cite3}, which demonstrated that a shared latent core can process heterogeneous inputs without a separate end-to-end architecture per modality. The continual-learning lineage runs through replay, reservoir sampling, EWC, SI, and gradient-projection methods, all of which address catastrophic forgetting from different directions \citep{kirkpatrick2017,lopezmanzanares2017,chaudhry2019,buzzega2020}.

The implementation here differs in emphasis. The central claim is not that MIME-style modality semantics are parsed directly inside model forward passes, but that explicit modality contracts at the runtime boundary reduce interface drift and make typed routing experimentally tractable. The empirical center of gravity is replay-path design: raw-input replay through the shared backbone matters much more in the current codebase than mild follow-on regularization. That systems emphasis places the work closer to deployable perception stacks than to another incremental attention variant.

\section{Methods}

\subsection{Architecture}

Each modality is routed through its own tower and then integrated through a shared cross-modal attention core. This design follows the Perceiver intuition that large heterogeneous inputs should be compressed into a tractable latent workspace \citep{cite2,cite3}, but it layers typed runtime contracts and bounded adaptation on top of that architectural core. The current codebase treats modality identity as a canonical runtime concept rather than an implicit property of tensor shape. MIME-style modality registries are used for validation and setup derivation at the contract boundary, while downstream model dispatch remains modality-key based.

Towers should be read as modality-specific encoders for related but semantically distinct sensory views. They are often different observations of the same world-state, user state, environment, or task context, but they should not be flattened together before the model has a chance to preserve their local structure and learn how they interact. Typical tower groupings could include camera + microphone + pose, wearable + room sensors + medical device telemetry, or robot state + environment sensors + operator signals. The general architectural claim is therefore that each tower should honor the semantics of its own modality, the shared core should learn cross-modal relationships, and replay should re-enter through the towers so those semantics do not drift during continual learning.

The current implementation should be read carefully here: these towers share one \texttt{PerceiverTower} family with modality-specific configuration, rather than three completely different neural block classes. The paper's implemented claim is therefore semantic distinction first. A more mature live deployment could specialize tower internals further for temporal wearable streams, sparse ambient context, or structured actuator telemetry, but that stronger specialization remains architectural direction rather than the present code-level claim.

Broader domain-specific tower examples and future live-system specializations are tracked outside the canonical paper lane in the repository's future concept library. They should be read as conceptual architecture patterns unless and until they are implemented and evidenced in the current codebase.

\paragraph{Current synthetic benchmark instance.}
The repository's current synthetic perception-side benchmark, \texttt{sensor\_streaming}, instantiates the general tower pattern with three canonical modalities:
\begin{itemize}[leftmargin=*]
  \item \texttt{smartwatch}: a 7-feature wearable stream representing body-side signals such as heart-rate and motion-derived measurements,
  \item \texttt{room\_env}: a 4-feature ambient stream representing environmental state such as temperature, humidity, CO\textsubscript{2}, and light,
  \item \texttt{robot\_arm}: a 9-feature actuation and kinematics stream representing joint and force/torque state.
\end{itemize}
Those three modalities are one benchmark instance, not the universal definition of a Sensory Perceiver deployment.

For live settings, the implementation now supports a stricter inference contract with structured per-modality payloads:
\begin{itemize}[leftmargin=*]
  \item \texttt{tensor}
  \item \texttt{valid\_mask}
  \item \texttt{status}
\end{itemize}
The preferred path is native mask-aware model support, with an explicit adapter available for legacy tensor-only models.

\subsection{Continual Learning}

The continual-learning program is replay-centric. Phase 1 used replay too high in the stack and failed badly. Phase 2 moved replay back to raw inputs with reservoir sampling, restoring replay gradients through shared feature extractors. The current tuned-core path improves on that configuration without changing the main conclusion: replay-path design is the strongest validated retention lever in this repository. That conclusion is consistent with replay-sensitive continual-learning baselines in the literature, where weighting and placement of replay constraints are first-order factors rather than implementation details \citep{chaudhry2019,buzzega2020}.

\subsection{Perception-Side Evaluation}

The completed synthetic perception-side ladder compares:
\begin{itemize}[leftmargin=*]
  \item \textbf{canonical}: typed modality routing with modality-specific towers,
  \item \textbf{merged}: one generic sensor stream without explicit typed modality separation.
\end{itemize}
It includes a baseline, a capacity-matched control, leave-one-out branches, binding corruption, and single-modality noise stress tests. Real-data evaluation now uses an explicit evidence taxonomy:
\begin{itemize}[leftmargin=*]
  \item \textbf{bootstrap}: first executable real-data runs used to validate ingestion and end-to-end operation,
  \item \textbf{canonical integrated}: bounded multi-dataset sequences promoted only after successful completion.
\end{itemize}

The active bootstrap and integrated real-data sources are:

\section{Experiments}

\subsection{Continual-Learning Lane}

The continual-learning lane uses Split-CIFAR-100 as the narrow but code-aligned benchmark for catastrophic forgetting. The canonical current result is the tuned-core six-seed family executed on Titan Node. The associated figures and tables are generated directly from artifact-backed runs in the results package.

\subsection{Synthetic Sensor Routing Lane}

The synthetic sensor ladder is complete. It is the strongest completed perception-side evidence path, but it remains synthetic and therefore bounded. Its purpose is to test whether typed routing matters under controlled stress rather than to stand in for broad real-world multimodal validation.

\subsection{Real-Data Lane}

The real-data lane is intentionally conservative. Bootstrap evidence is includable now:
\begin{itemize}[leftmargin=*]
  \item \texttt{real-audio-seq-001} on \texttt{speech\_commands}
  \item \texttt{real-seq-004} on \texttt{wisdm}
\end{itemize}
Canonical integrated audio and sensor evidence are now promotable:
\begin{itemize}[leftmargin=*]
  \item \texttt{real-audio-seq-003} on \texttt{speech\_commands}, \texttt{esc50}, \texttt{urbansound8k}, and \texttt{fsd50k}

\end{itemize}
Deferred legacy sources remain explicit but are no longer part of the active bounded chain:
\begin{itemize}[leftmargin=*]

  \item \texttt{ubiqlog}: replaced operationally by \texttt{realworld\_har}

The completed synthetic sensor ladder establishes the strongest finished perception-side result in the repository. Canonical typed routing is ahead on the baseline, the capacity-matched control, all leave-one-out branches, the binding-corruption branch, and two of the three single-modality noise branches.   \item drop smartwatch: $+0.3317$

  \item noise smartwatch: $+0.0633$
  \item noise room environment: $+0.0617$
  \item noise robot arm: $-0.0933$
\end{itemize}
The supervisor's final state for the ladder is \texttt{canonical-dominant}. The important nuance is that the result is strong but not uniform: \texttt{noise\_robot\_arm} is the one completed branch where merged routing wins.

Figure~\ref{fig:real-data-evidence-overview} summarizes the current real-data package state. The completed bootstrap results are:

\section{Discussion}

\subsection{What Is Strongest Right Now}

The strongest evidence in the repository is still replay-centric continual learning. The central mechanistic insight survives every implementation pass so far: replay must reach shared feature extractors, not only late task heads. The tuned-core Split-CIFAR-100 result is therefore still the main quantitative anchor for the paper.

\subsection{What The Synthetic Sensor Ladder Adds}

The completed synthetic sensor ladder materially strengthens the broader perception story. It shows that typed routing is not just runtime hygiene; it changes performance on a controlled benchmark, survives a capacity-matched control, and remains favorable under multiple structured stressors. At the same time, the \texttt{noise\_robot\_arm} reversal prevents overclaiming. The right interpretation is ``strong controlled support'' rather than ``uniform dominance.''

\subsection{What The Real-Data Lane Adds}

The real-data lane now matters because it prevents the project from staying trapped in synthetic-only evidence. Bootstrap Speech Commands and WISDM runs prove that the real-data path is executable. Both integrated sequences have now cleared the evidence gate: \texttt{real-audio-seq-003} completed all expected audio datasets with no blocked entries, and \texttt{real-sensor-seq-002} completed all expected sensor datasets with no blocked entries. This bootstrap-versus-canonical split remains the main guardrail against overstating progress while Titan is still resolving bounded evidence chains.

\subsection{Claim Surface Versus Evidence Surface}

The architectural concept is broader than the current evidence. That is acceptable only if the manuscript stays explicit about the gap. Today the evidence hierarchy is:
\begin{enumerate}[leftmargin=*]
  \item strongest validated result: replay-centric continual learning,
  \item strongest completed perception-side result: synthetic sensor routing ladder,
  \item completed bootstrap real-data evidence: Speech Commands and WISDM,
  \item canonical integrated real-data evidence: not yet promotable.
\end{enumerate}
That hierarchy is the one this manuscript defends.

\subsection{Practical Interpretation}

For an applied reader, the present result is not a finished universal perception product. It is a disciplined blueprint for building domain-specific systems that:
\begin{itemize}[leftmargin=*]
  \item keep modality identity explicit,
  \item validate modality semantics at the runtime boundary,
  \item remain useful when one stream is degraded,
  \item and adapt over time without constant full retraining.
\end{itemize}

\section{Conclusion}

Sensory Perceiver now has one coherent evidence story. Replay-centric continual learning remains the strongest validated result, with the tuned-core six-seed Titan family as the current quantitative anchor. The completed synthetic sensor ladder provides the strongest finished perception-side evidence, showing a strong but not unconditional advantage for typed routing. Bootstrap real-data evidence on Speech Commands and WISDM establishes that the real-data path is executable, while canonical integrated promotion remains blocked until bounded sequences finish cleanly.

This is the right stopping point for the current manuscript. It does not overclaim incomplete evidence, it preserves deferred legacy sources such as AudioSet and UbiqLog, and it keeps the broad machine-perception framing tied to what the code and artifacts actually support. If future bounded sequences finish cleanly, the next revision can promote them into the canonical results package. Until then, the present paper should be read as a code-aligned architecture paper with a strong continual-learning core, a completed synthetic perception-side ladder, and a cautiously advancing real-data evidence path.
