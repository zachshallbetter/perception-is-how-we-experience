# Supplementary Papers Strategy

## Claim Scope Policy

Supplementary documents are secondary analyses and planning artifacts.
They are not authoritative for main-paper benchmark claims, implementation status, or final empirical tables.
Use `paper/sections/00-implementation-status-matrix.md` and `paper/sections/06-results.md` for canonical claim authority.

## Purpose

This directory tracks extension workstreams:
1. architecture-focused analysis,
2. orchestration/systems analysis,
3. domain application studies.

These tracks are intended to expand and contextualize the main paper, not redefine canonical results.

## Normalization Rules

- Supplementary numeric results are treated as exploratory unless mirrored in canonical sections.
- Any benchmark-scale claim must reference canonical sections explicitly.
- Status language must remain implementation-aligned (implemented, partial, planned).

## Current Status

- Architecture supplementary: exploratory analysis aligned to canonical methods and limits.
- Orchestration supplementary: systems framing aligned to current runtime/services status.
- Applications supplementary: domain scenarios and evaluation templates; not canonical empirical evidence.
